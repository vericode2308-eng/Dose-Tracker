## 2026-09-29 — Notification buttons after swiping the app away

- **Request:** Fix Take Now, Skip, and Snooze failing from Android reminders after closing the app by swiping it away (not Android Force stop), and record the correction.
- **Cause:** Expo SDK 57's Android local-notification serializer supplies custom payloads as `content.dataString`. Its UI response listener parses that JSON into `content.data`, but the headless TaskManager callback receives the raw serialized response. The shared dose resolver read only `data`, silently ignored the background action, and left the notification visible. The existing task registration and native action delivery worked; this was not a missing Android permission.
- **Correction:** The shared response reader accepts mapped `data` and falls back to parsing raw `dataString`, preserving the existing payload version, medicine/schedule ownership, profile, and occurrence checks. Invalid payloads cannot perform dose actions. Concurrent task/UI delivery shares one action attempt; a bounded completion cache prevents replay in the same runtime, failed writes remain retryable, and recurring deliveries retain distinct identities. Successful Android actions also clear the last response.
- **Snooze replay:** Emulator testing exposed a second issue: opening the app can replay a headless response into a separate runtime and extend the snooze again. SQLite now compares the notification delivery time with the stored snooze deadline inside the transaction and returns the existing deadline for an older notification. A later snooze alarm or deliberate in-app snooze can still defer the dose. Replaying an expired snooze cannot create an immediate replacement alarm. No new persistence table or schema migration is needed.
- **Files:** `src/notificationManager.js`, `src/notificationManager.d.ts`, `src/database.js`, `src/database.d.ts`, `tests/notificationManager.test.cjs`, `tests/database.test.cjs`, `docs/CORRECTIONS_LOG.md`. No dependency, database schema, permission, or native-config changes.
