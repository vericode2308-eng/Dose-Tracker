# DoseTracker Terms: code evidence inventory

> Historical drafting notes. Superseded on 2026-09-29 where inconsistent with the current Privacy Policy and `docs/GOOGLE_PLAY_POLICY_AUDIT.md`. VeriCode / support@vericodestudio.com and adult operation (18+) are confirmed. Sentry now uses explicit opt-in for limited JavaScript errors. Older no-telemetry and missing-policy-link statements below are no longer current.

Audit date: 26 September 2026. Scope: shipped application source in `src/`, Android module in `modules/`, app configuration, dependencies, and current UI. `PLAN.md` describes future work and is not evidence that a feature has shipped. This inventory is a product audit, not a conclusion about regulatory status or applicable law.

| Term-relevant finding | Code evidence and implication |
| --- | --- |
| Product and platforms | The app presents itself as medicine management for users and family members (`src/app/welcome.tsx:12-19`). It has Today, History, and Settings tabs (`src/app/(tabs)/_layout.tsx:6-14`) and Android, iOS, and web configuration (`app.json:10-31`). Web reminder delivery is unsupported (`src/notificationManager.js:69-70`). |
| First use | Onboarding offers local profile setup, optional notification permission, then marks setup complete (`src/app/_layout.tsx:47-63`; `src/app/profile.tsx:45-56`; `src/app/ready.tsx:13-18`). The completion flag is in AsyncStorage (`src/features/onboarding/storage.ts:4-19`). There is no Terms acceptance step in this route flow. |
| Accounts and identity | The welcome page says no account or sign-up (`src/app/welcome.tsx:17-19`). A profile is a local person record, not a remotely authenticated account (`src/database.js:147-159`; `src/database.js:517-538`). Profile switching selects an active local profile without an individual sign-in (`src/features/profiles/ProfileSwitcher.tsx:48-63`; `src/database.js:509-515`). Do not draft passwords, account recovery, or remote account suspension clauses. |
| Device lock | Optional app lock stores its on/off flag in SecureStore, calls the platform biometric/device-credential prompt, and returns false on failed authentication (`src/features/security/SecurityManager.js:5-46`). It gates the entire navigator at launch and after backgrounding (`src/features/security/AppLock.tsx:28-50`, `:67-101`), and enabling/disabling requires authentication (`src/features/security/DeviceAuthenticationSettingsScreen.tsx:21-39`). The UI warns that any enrolled biometric user or person who knows the screen lock can enter; app lock does not encrypt the database or exports (`src/features/security/DeviceAuthenticationSettingsScreen.tsx:45-51`). |
| User-entered health information | Users can enter profiles including name, relationship, photo, birth date, and notes (`src/app/profile.tsx:75-114`); medicine name, strength, dose, purpose, instructions, notes, schedule, and stock (`src/features/medicines/AddMedicineScreen.tsx:55-75`, `:100-117`). SQLite holds profiles, medicines, schedules, dose history, snoozes, and reminder issue logs (`src/database.js:83-125`, `:135-173`). Photos are copied into the app document directory on native platforms (`src/features/onboarding/photos.ts:17-25`). |
| Tracking and history | The Today screen offers Taken, Skipped, and Snooze actions (`src/features/today/TodayHomeScreen.tsx:44-72`). A Taken entry records an actual time and reduces tracked stock; a snooze is separately persisted (`src/database.js:349-385`). History reads local SQLite records by date and profile (`src/features/history/HistoryScreen.tsx:20-45`; `src/database.js:429-454`). Users supply the underlying medication details; the app does not verify prescriptions. |
| Reminder scope and limits | Native recurring notifications are scheduled for ongoing daily or selected weekday patterns only. As-needed schedules have no fixed reminder, and course bounds, future starts, and intervals are rejected for automatic reminders (`src/notificationManager.js:40-53`). The UI nevertheless lets users save every-N-day/hour and bounded schedules, then warns if reminder setup is unsupported (`src/features/medicines/AddMedicineScreen.tsx:15-21`, `:100-128`). There is no delivery guarantee: permission/channel/exact-alarm state is checked, and the code explicitly says delivery depends on system restrictions (`src/notificationManager.js:69-100`). The diagnostic screen cannot prove every delivery or deep-sleep miss (`src/app/reminder-status.tsx:24-34`). Android exact-alarm and notification permissions are declared (`app.json:22-26`), with native settings links (`modules/dose-alarm-access/android/src/main/java/expo/modules/dosealarmaccess/DoseAlarmAccessModule.kt:17-33`). |
| Reminder content and controls | Users may choose show/hide/no information, sound, vibration, snooze duration, and reminders on/off (`src/features/settings/storage.ts:5-21`; `src/features/settings/SettingsHomeScreen.tsx:145-153`). Android notification channel visibility maps to PUBLIC/PRIVATE/SECRET and channel sound/vibration are configured (`src/notificationManager.js:75-83`). A medication-style test notification is scheduled ten seconds ahead (`src/notificationManager.js:115-126`). System-level settings can override app preferences (`src/notificationManager.js:84-100`). The default privacy mode is show content (`src/features/settings/storage.ts:14-20`), which can display medication details on the lock screen (`src/notificationManager.js:10-14`). |
| Storage and sharing | SQLite is opened on-device (`src/database.js:19-20`, `:201-212`); onboarding and preferences use AsyncStorage (`src/features/onboarding/storage.ts:4-19`; `src/features/settings/storage.ts:3-45`); only the app-lock flag uses SecureStore (`src/features/security/SecurityManager.js:5-31`). Android app backup is disabled in config (`app.json:13-14`). The export creates a **preferences-only** JSON file and invokes the OS share sheet; the temporary file is deleted afterward (`src/features/settings/backup.ts:7-33`). Restore uses a selected local file, validated as preferences-only (`src/features/settings/backup.ts:35-62`). No profile, medicine, or dose-history export is implemented (`src/features/settings/SettingsHomeScreen.tsx:163-165`). A selected sharing destination may have its own terms and privacy practices; app code does not choose or operate that destination. |
| Paid features | The onboarding UI says all features are free and no subscription is required (`src/app/welcome.tsx:17-19`). `package.json:5-47` contains no billing or in-app purchase SDK; the audited app source contains no purchase flow. Do not add pricing, renewal, cancellation, or refund provisions for this build. Distribution-store charges or a future paid release require a fresh audit. |
| AI and public content | The audited `src/`, `modules/`, `app.json`, and `package.json` have no AI model/API integration, generation flow, user-to-user posting, or social feed. The app manages user-entered records locally (`src/database.js:83-125`; `src/features/medicines/AddMedicineScreen.tsx:93-121`). Omit AI-output and public-posting/moderation clauses. This is a scoped negative finding, not a guarantee about future builds. |
| Usage boundaries | Validated profile fields cap name at 80, relationship at 40, and notes at 200 characters (`src/database.js:517-523`); preference import files cap at 1 MiB (`src/features/settings/backup.ts:4-5`, `:35-50`). Medicine and schedule data have structural validation (`src/database.js:26-70`, `:229-241`). No server rate limit, quota, or abuse-enforcement system was found in the audited source. Do not invent a remote service acceptable-use policy. |
| Third-party dependencies | OS-level notifications, alarm access, biometric/device credential prompts, photo picker, file picker, and share sheet underpin the app (`app.json:32-82`; `src/notificationManager.js:56-83`; `src/features/security/SecurityManager.js:1-3`; `src/features/onboarding/photos.ts:1-6`; `src/features/settings/backup.ts:21-37`). The repository has no app-specific cloud, analytics, or billing integration in the audited app source/dependency list (`package.json:5-47`). Platform app-store terms may govern distribution, but no specific store is configured here. |
| Archiving, deletion, and discontinuance | Medicine deletion removes its schedules and history through SQLite cascades, and cancels related reminders (`src/database.js:99-114`, `:321-325`; `src/notificationManager.js:218-249`). Archiving a profile keeps data but stops its reminders (`src/app/profile.tsx:121-122`; `src/database.js:540-552`; `src/notificationManager.js:197-212`). “Erase all data” cancels scheduled/presented notifications, clears SQLite, preferences, secure app-lock flag, onboarding, and matching local profile photo files; its UI warns partial erasure may need retry (`src/notificationManager.js:160-169`; `src/features/settings/SettingsHomeScreen.tsx:97-115`, `:165`). No remote account or remote suspension/termination control exists in the audited app source. Files the user already shared or copied outside the app are outside this erasure path. |

## Release issues affecting legal accuracy

1. `src/app/notifications.tsx:42` says **“Never miss a dose.”** That absolute claim conflicts with the permissions, scheduling, and delivery limitations at `src/notificationManager.js:40-53`, `:69-100`, and `src/app/reminder-status.tsx:32-34`. The marketing/UI claim should be corrected before release; Terms alone cannot cure it.
2. `src/features/medicines/AddMedicineScreen.tsx:149` promises “low-stock alerts and never run out,” while `src/notificationManager.js:314-359` schedules medication dose reminders, not a separate stock-alert channel. Verify and revise this claim before publication.
3. `LICENSE:1-20` names **650 Industries, Inc. (Expo)** as copyright holder. This appears to be an inherited template license and does not establish ownership or licensing of DoseTracker code. Confirm the intended app license and all third-party notices before an IP clause is finalized.
4. No Terms/Privacy Policy link or click-through appears in the first-use flow (`src/app/_layout.tsx:47-63`; `src/app/welcome.tsx:21-27`), and the Settings “Privacy information” row opens static About copy (`src/features/settings/SettingsHomeScreen.tsx:153-166`). Publication needs discoverable legal/privacy text and a decided acceptance/notice mechanism.
5. The app is described as “entirely offline” (`src/app/welcome.tsx:17`), and there is no app-specific network integration in audited source. Confirm build-time SDK behavior, crash reporting/telemetry, update channel, and distribution-store processing separately before making an absolute privacy claim.
